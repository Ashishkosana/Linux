What does a "container" actually change?

One command starts a shell in fresh namespaces. Nothing is copied or virtualised. The kernel simply shows that shell a different view of the same machine. Select a namespace to compare what the host sees with what the shell sees.

The command

unshare --pid --fork --mount-proc --uts --net --ipc --mount sh

Pick a namespace

All ten namespace handles, from /proc/self/ns

Each handle is an inode number. Equal numbers mean the shell shares that view with the host. Different numbers mean it has its own. Cgroup, time and user were not requested, so those three stay shared.

Process table size

A container is an ordinary process with some of its namespaces swapped out. The shell is PID 1 in its own world, but the host kernel still schedules it as PID 193's child.
