Experiment 03 · PostgreSQL 16 + Python workers on a 4-core VM

A compute cloud in miniature

A cloud is a queue, some workers and a database that keeps score. Here the database holds 48 jobs. Each job counts the primes in a 60-million-number range. Workers claim jobs, compute, and write the answer back. The same 48 jobs were run with 1, 2, 4 and 8 workers.

Scaling: measured against ideal

Speedup is the 1-worker time divided by the N-worker time.

The SQL doing the work

Many workers ask for a job at once and none may get the same one. FOR UPDATE SKIP LOCKED makes each worker lock one queued row and lets the others skip past it. The queue needs no separate broker.

UPDATE jobs SET status='running', worker=$1, started=clock_timestamp()
WHERE id = (SELECT id FROM jobs WHERE status='queued'
            ORDER BY id FOR UPDATE SKIP LOCKED LIMIT 1)
RETURNING id, lo, hi;

Correctness check from the database: every run produced primes in total, so no job was lost or done twice.
